# Node.js + MongoDB Containerization Project

Цей проект налаштований для роботи в ізольованих контейнерах за допомогою Docker та Docker Compose. Це гарантує, що додаток та база даних будуть працювати однаково на будь-якому комп'ютері.

## 🏗 Архітектура контейнеризації

Проект складається з двох основних сервісів:
1.  **app**: Node.js додаток (Express), який працює на порту `5001` всередині контейнера і прокидається на порт `5555` локально.
2.  **db**: База даних MongoDB, яка працює на стандартному порту `27017` і доступна локально через порт `1234`.

### Роль основних файлів:
-   **[Dockerfile](file:///Users/v.kostetskyi/Documents/okten/NodeJs/Dockerfile)**: Описує, як збирається образ нашого додатку (базовий образ node:20-alpine, копіювання `package.json` та встановлення залежностей).
-   **[docker-compose.yml](file:///Users/v.kostetskyi/Documents/okten/NodeJs/docker-compose.yml)**: Головний файл оркестрації. Він пов'язує додаток та базу даних, налаштовує мережу, порти, томи (volumes) для збереження даних та змінні оточення.
-   **[mongo-init.js](file:///Users/v.kostetskyi/Documents/okten/NodeJs/mongo-init.js)**: Скрипт ініціалізації бази даних, який автоматично створює користувача при першому запуску контейнера `db`.
-   **[.env.db](file:///Users/v.kostetskyi/Documents/okten/NodeJs/.env.db)**: Налаштування для бази даних (логін, пароль, назва БД).
-   **[.env](file:///Users/v.kostetskyi/Documents/okten/NodeJs/.env)**: Конфігурація самого додатку, включаючи JWT секрети та налаштування пошти.

## 🚀 Команди для роботи

Нижче наведено список основних команд для керування контейнерами:

| Команда | Опис |
| :--- | :--- |
| `docker-compose up` | Запуск усіх сервісів (вивід логів у термінал). |
| `docker-compose up -d` | Запуск у фоновому режимі (detach mode). Контейнери працюють, але термінал вільний. |
| `docker-compose build` | Перезібрати образи (потрібно після зміни Dockerfile або додавання нових залежностей). |
| `docker-compose down` | Зупинити та видалити всі контейнери проекту. |
| `docker-compose stop` | Просто зупинити контейнери (не видаляючи їх). |
| `docker-compose restart` | Перезапустити всі сервіси. |
| `docker-compose logs -f` | Переглянути логи контейнерів у реальному часі. |
| `docker-compose exec app sh` | Зайти всередину працюючого контейнера додатку (через shell). |

## 🛠 Налаштування (Setup)

1.  **Створення файлів оточення**: Переконайтеся, що файли `.env` та `.env.db` заповнені коректно.
2.  **Перший запуск**:
    ```bash
    docker-compose up --build
    ```
    Це змонтує образи та запустить сервіси. База даних автоматично ініціалізується за допомогою `mongo-init.js`.
3.  **Доступ до API**: Додаток буде доступний за адресою `http://localhost:5555`.
4.  **Доступ до БД**: Ви можете підключитися до MongoDB через `mongodb://user:user@localhost:1234/nodejs-express-db`.

## ❓ Навіщо взагалі потрібен Docker?

Docker вирішує кілька критичних проблем розробки:

1.  **"У мене на комп'ютері працює, а у інших — ні"**: Docker упаковує всі залежності (Node.js версії 20, бібліотеки, саму ОС Alpine) прямо в образ. Це гарантує, що проект запуститься у колеги або на сервері точно так само, як у вас.
2.  **Ізоляція**: Ви можете тримати різні версії Node.js або бази даних для різних проектів, і вони не будуть конфліктувати між собою.
3.  **Легкість налаштування**: Замість того, щоб встановлювати MongoDB, Node.js та інші інструменти безпосередньо в систему, ви просто натискаєте одну кнопку (запускаєте команду), і все готово.
4.  **Чистота системи**: Коли ви закінчите працювати, ви можете видалити контейнери, і ваш Mac залишиться чистим від "сміття" баз даних та конфігурацій.

## 🛣 Що робити далі?

Тепер, коли проект контейнеризований, ось ваші подальші можливості:

-   **Деплой на сервер (VPS/Cloud)**: Ви просто копіюєте ці файли на сервер (наприклад, DigitalOcean або AWS), де встановлений Docker, і запускаєте ту саму команду `docker-compose up`. Проект запрацює миттєво без встановлення бази даних на сервер.
-   **CI/CD (Автоматизація)**: Ви можете налаштувати GitHub Actions або GitLab CI, щоб при кожному пуші коду Docker автоматично збирав образ і перевіряв, чи проект запускається.
-   **Масштабування**: Якщо ваш проект отримає багато користувачів, ви зможете легко запустити 3-5 копій контейнера `app` за допомогою балансувальника навантаження (наприклад, Nginx), щоб додаток працював швидше.
-   **Робота в команді**: Будь-який новий розробник у вашій команді зможе почати писати код за 5 хвилин, просто клонувавши проект та запустивши Docker.

## 🌍 Розробка (Local) vs Продакшн (Real Site)

Щоб краще розуміти, як проект працює у реальному світі, важливо розрізняти ці два стани:

### 🏠 Локальна розробка (Ваш комп'ютер)
- **Де дані?** Зберігаються у вас на диску в папці `mongo_db`.
- **Docker**: Ви запускаєте його тільки тоді, коли працюєте над кодом. Коли ви вимикаєте комп'ютер, сайт "падає", але це нормально для розробки.

### 🚀 Продакшн (Реальний сайт в інтернеті)
Для того, щоб сайт був доступний усім 24/7, використовуються два підходи:

1. **Хмарна база (Atlas)**: Дані зберігаються в інтернеті на серверах MongoDB. Ваш проект підключається до них через спеціальний URL. Вам не потрібно думати про збереження файлів чи місце на диску.
2. **Окремий сервер (VPS)**: Ви орендуєте комп'ютер, який ніколи не вимикається. Там працює Docker з вашим проектом. Дані зберігаються на диску цього сервера.

**Як перемикатися?**
Ви просто змінюєте назву бази в файлі `.env`. Вдома там вказана ваша локальна база Docker (`db`), а для реального сайту там буде вказана адреса вашого хмарного кластеру (`cluster0...`).
